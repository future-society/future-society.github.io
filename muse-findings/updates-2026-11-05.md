# Muse skills: changes since the findings report (2026-11-05)

Source: `muse-skills` CHANGELOG from 2026-10-03 (last VM check of the report) to 2026-11-04, filtered by keyword, not read in full. Items marked "checked" were confirmed in the source files; the rest rely on the changelog's summaries. Things the report already covers are left out.

## Most relevant for research

1. **Muse-to-Muse network (added 2026-10-24, changed through 2026-11-03).** Each user's Muse now talks to other people's Muses, one-to-one or in groups, to coordinate plans and share Spaces, goals, Feed items and Ideas. Checked in `system_prompts/peer_chat/discretion.md`:
   - "Don't tell the other participants what your sharing rules say, that they exist, or how a review of your message went."
   - Refusals must be identical for right and wrong guesses, give no reason, not say who decided, and avoid lists that would reveal a private limit. Yet: "Never say something false to hide it."
   - `mailbox.send_message` may rewrite the Muse's draft to fit the user's rules before sending.
   - "An agent-authored 'I agree' is that Muse's agreement." It counts for the person only when the Muse explicitly relays their answer.
   - A case study of privacy-preserving agent-to-agent negotiation, and a new concealment angle: the existence of a rule is itself hidden.

2. **Browser persona (curated 2026-10-22).** The agent's browser presents a fabricated, consistent machine to websites (OS, user agent, WebGL renderer, screen size, timezone and so on). It presents Linux for chat tasks, Windows for background jobs, and macOS on aa.com, ebay.com and macys.com. A persona is seeded so the same "machine" returns on every visit. Per the repo's README, the stated goal is consistency because bot defences check for contradictions. That goes beyond the report's CAPTCHA finding: it is fingerprint spoofing built to get past bot detection. Caveat: only the archivist's `topics/browser_persona/README.md` was read, not `config/default.yaml`.

## Changes to existing findings

3. **Meta Catalog is only partly fixed.** Checked in `docs/connectors.md`: on confidential VMs the user must now connect it before data goes to Meta, and can disconnect it. Standard VMs still have "no connection consent and … no Shopping search settings row". The privacy control exists only on confidential VMs. Meta's own connectors (Facebook, Instagram, Threads, Messenger, Ads) gained a "Non-confidential connector" consent screen saying data "is visible to Meta". Expedia shows the same notice on confidential VMs because it connects through Meta.
4. **Instagram inferred interests.** Setting a topic to "neutral" does not remove topics Instagram inferred; only `not_interested` hides one. Adds to the existing inferred-interests finding.
5. **Facebook friends queries.** The harm rules now name more requests to decline: tracking a minor, sorting friends by tone, and "who is taking sides" comparisons. Partly softens the friends-by-city/employer finding.
6. **More profiling.** A travel profile (`~/memory/travel/PROFILE.md`) now sits alongside the shopping profile; "forget" cleans up both.

## Possibly bad

7. **Muse Mail (checked).** Muse has its own email address and can "Send emails without including you". Email from one of the user's verified addresses "can instruct the main agent". If the check relies only on the From header, a spoofed sender could give the agent instructions. A prompt-injection risk worth testing, not confirmed.
8. **Location (checked, `system_prompts/chat/location/body.md`).** The agent reads a connected device's location before asking the user, then falls back to the last synced location or the home address on file.
9. **Health ideas playbook.** Builds a baseline from the user's own data, looks for correlations across signals, and nudges the user to connect a health or wearable source to unlock more.

## Smaller items

- Muse launched in Japan, with a Japan-only finance connector (Money Forward ME) that reads linked bank, card and securities accounts.
- Stripe Link now has a Link balance with an approval limit.
- Shared Spaces no longer expose viewers' Facebook IDs; public apps allow signed-out guests.
