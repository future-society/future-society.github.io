# Agent notes for future-society.github.io

## Site structure
- Single-page site duplicated per language (`index.html`/`.de`/`.fr`), no
  build step/templating. Content changes apply to all three; translate UI
  chrome, leave names/paper titles/citations as-is.
- Grep HTML comments like `<!-- FOCUS AREAS -->` to jump to the matching
  `<section id="...">`.
- Data-driven sections (Team, Projects, Ways to participate) render from a JS
  array at the bottom of each file (or `assets/team.js` for Team) — edit the
  array, not generated markup.

## Focus Areas publications
- Each `.focus-card` (exactly 4 children: num, h3, p, `.focus-publications`)
  has its own toggle+list (JS-toggle like Participate's `.way-body`, not
  `<details>` — animating that was jerky in Firefox). List items: `<a>` title
  to DOI/landing page + `.focus-pub-meta` "Venue · Year" span. Authors
  omitted, titles not translated. No fabricated URLs — leave plain text if no
  DOI/landing page exists.

## Collapsible content
- Default: plain `<details><summary>`, CSS-only +/– marker. Exception: Focus
  Areas publications use the JS-toggle above.

## Non-website / email-task requests
- Not every email instruction maps to a site edit (LinkedIn drafts, research
  asks are pure drafting tasks). No email-sending tool exists — never claim
  an email was sent; write the deliverable to a file as the OUTPUT_FILE.
  FuSo's LinkedIn company page is login-walled — ground drafts in
  `llms.txt` instead and say so explicitly.

## Social icons
- Inline-SVG icons (not `<img>`/icon fonts) in nav (`.nav-social`, LinkedIn
  only) and Contact (`.contact-social`, LinkedIn + BlueSky). Reuse existing
  `<path>` markup; add a new platform to both places if the ask is
  "site-wide".

## CSS grid
- Sections use a shared `.grid`. New full-width blocks typically use
  `grid-column: 3 / -1`, must be added to the tablet-breakpoint reset list,
  plus a mobile-stacking rule if the block is itself multi-column.

## Nav submenu / audience deep links
- Participate's `nav-sub` links to `#participate-<audience>` hashes; a
  hashchange router calls `filterWays()` and scrolls to `#participate`.
  Submenu CSS is scoped to `#navMenu`/`#navMenu > li`, not `nav ul` —
  reverting to `nav ul` breaks its positioning.

## AI+X deck (`ai+x/index.html`)
- Standalone single-file reveal deck; slide order = DOM order of `.slide`
  sections, not the id/aria-label numbers (those, plus pos/prev-next chrome,
  are hardcoded — keep in sync manually on reorder). `data-time` is a
  cumulative pacing cue, keep roughly monotonic. Don't hand-edit with sed
  (huge inline-base64 lines) — extract `<section>` boundaries via `grep -n`
  and reassemble with a script. The Programme slide's own agenda durations
  are a separate schedule from `data-time` — keep the total (2.5h) unchanged
  unless told otherwise.

## Project subsites / standalone pages
- `2028gid/`: standalone essay, deliberately unlisted (no site link, not in
  sitemap.xml) — keep it that way unless asked.
- `muse-findings/`: bare HTML fragments (no `<html>`/`<body>` tags). Needs
  GoatCounter + `analytics.js` pair at the very end — easy to forget since
  it isn't copied from a templated `index*.html`.
- Vanity redirects (`cocoda/`, `decode/`): folder + `index.html` using
  meta-refresh + `location.replace` + canonical + noindex (GitHub Pages has
  no server-side redirects). Copy an existing folder to add another; keep
  out of `sitemap.xml`.

## Hero wording
- `.hero-chain`: "Full Stack: Analyze › Build › Deploy › Evaluate", plain
  text (not `.block-item` chips — tried, rejected); each `›` bundled with
  the following step in a nowrap span. Spelling "Full Stack" (two words, no
  hyphen) everywhere, all languages.
- Hero song easter egg (`.song-egg`): note plays a per-language song via a
  shared `<audio>`. Its position formula off `.hero-logo` is load-bearing —
  don't move it to the top-right (collides with the lang switch). Picker
  codes are the *song's* language, not the page's.

## Asset hygiene
- Songs live in `assets/audio/`, all `preload="none"`. Below-the-fold images
  get `loading="lazy"`; above-the-fold (nav/hero) don't.

## LinkedIn post draft requests (recurring email task)
- Find world news ≤2 days old matching a FuSo focus area, draft a LinkedIn
  post tagging relevant entities, tie it to a FuSo publication (Focus Areas
  `.focus-pub-list`s + `llms.txt`). Must not repeat a **news story**; reusing
  a **publication** on a different story is fine. New drafts go in
  `/linkedin-suggestions/` (older root-level `linkedin-post-draft*.md` files
  predate that convention; as of 2026-10 both locations can be empty — that
  just means no drafts have been made yet, not a lost history). No email
  tool exists — the draft file is the OUTPUT_FILE.
- Publication author names often aren't on the site (titles not translated,
  authors omitted per Focus Areas convention) — WebSearch the DOI/arXiv
  title directly (ACM/DOI pages themselves frequently 403 WebFetch) to find
  co-authors and confirm which FuSo person to credit/tag; cross-check the
  name against `llms.txt`'s Key People/Wider Research Team list.
- A regulator-vs-industry news cycle (e.g. a frontier-lab CEO publicly
  asking for binding AI regulation, political figures reacting) pairs
  naturally with FuSo's own transparency/audit papers on the *same*
  regulatory mechanism (e.g. an EU AI Act Article 53 disclosure-quality
  study) even without a shared named entity — the angle is "here's how well
  a similar mandate already works in practice," not a literal subject
  match.
- Before picking a publication: `grep -l "doi.org\|arxiv\|openreview"
  linkedin-suggestions/*.md linkedin-post-draft*.md` and check matches
  against the site's focus-pub-lists — authoritative; don't hardcode a
  "used so far" list here, it drifts. Prefer a less-recently-used
  publication over an overused one (Article 40(12) audit paper, GPAI
  summary-framework paper — fine as fallbacks since their arguments
  generalize, but check for a better-fitting, less-used option first). A
  stuck publication's match often comes from its *methodology/design
  philosophy* or a *second stated application* (check Focus Areas "how"
  text + author bios), not its literal subject matter. The two books (*AI
  and Law*, Routledge 2024; *Designing for Privacy*, Springer 2018) sit only
  in `llms.txt`/JSON-LD, not Focus Areas — valid anchors, no DOI exists.
  PermitBot (ICAIL 2026) has no findable URL/news match on its own despite
  repeated tries — treat WebSearch claims about its authorship/study
  specifics as unverified/likely hallucinated; no author is credited on the
  site either, so don't attribute it to a named team member. It was finally
  used (California SB 574 lawyer-AI-use law, Oct 2026 draft) by matching its
  *topic* (proactive legal-chatbot design) to a law's content rather than
  searching for PermitBot-specific news. A single underlying story (e.g. an
  OpenAI agent-breach disclosure) can resurface in later news cycles with
  new angles (fresh congressional bill, new disclosure) — still treat it as
  the same "topic" if it's a continuation of an already-mined incident
  cluster, not a fresh pick, even when the specific article is ≤2 days old.
- WebSearch is unreliable for date-sensitive claims — verify against a
  primary source (WebFetch the original outlet, not an aggregator) before
  treating a story as fresh. Recurring staleness traps: SEO blogspam
  inventing agency names/dates; an old story recapped under a new
  headline/date; invented events; a months-old product launch
  re-summarized as new; a bill's real-world year silently swapped (a "2026"
  result can describe something that actually happened in 2024). If only
  stale/used stories turn up, document rejected candidates in the draft and
  use the freshest genuinely-new story available rather than force a stale
  one through.

## FuSo Talks event list
- `.event-item`: name (+ optional `.event-tag`/`.bbl-tag` pill) / speaker /
  optional coop line / meta-row. `.bbl-tag` normally reads "Brown Bag Talk";
  a project-tied talk instead gets "Featured `<project>` Talk", project
  linked. Tag text stays English across languages; speaker prefix/prose
  translated.
- `#funders` is only for FuSo's own research-grant funders — a one-off event
  sponsor instead gets an `.event-coop`-styled line with
  `.event-sponsor-logo` from `assets/images/sponsors/` (translate "Sponsored
  by", not the sponsor name). `sosy2027.org` is external/unreachable from
  here — "add to sosy2027" requests go via this site's own Upcoming Events
  entry for it instead.

## Dark mode
- `data-theme="dark"` on `<html>`, persisted to `localStorage` only on an
  explicit toggle (otherwise follows OS `prefers-color-scheme` live); a
  blocking inline `<head>` script avoids flash. Button is two inline SVGs
  outside `#navMenu` — update in all 3 language files.
- Stylesheet re-themes for free via 5 root vars (`--black/--white/--gray/
  --mid/--accent`) — use these for new CSS, not raw hex. White-text-on-
  accent-fill buttons need the separate `--accent-contrast` + literal `#fff`
  instead, since `--accent` is relightened for dark contrast. A new literal
  hex needing dark theming: convert it in place to `--text-body`/
  `--text-quiet`/`--divider` rather than adding a `[data-theme="dark"]`
  override rule — some selectors have same-specificity hover states an
  override would permanently beat.
- Hero/footer logo SVGs have an opaque white circular fill, rendering as a
  visible disc in dark mode; no transparent variant exists — out of scope
  unless asked.
