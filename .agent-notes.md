# Agent notes for future-society.github.io

## Site structure
- Single-page site, duplicated per language: `index.html` (EN), `index.de.html`,
  `index.fr.html`. No templating/build step — each is a full standalone copy.
  Any content change requested for "the website" generally needs to be applied
  to all three, with UI chrome (labels, buttons) translated but people's names,
  paper titles, and citations left as-is.
- Section markers use HTML comments (`<!-- FOCUS AREAS -->` etc.) matching the
  `<section id="...">` right below them — grep for the comment to jump fast.
- Data-driven sections (Team, Projects/"Get concrete", Ways to participate) are
  rendered by inline `<script>` at the bottom of each HTML file (or
  `assets/team.js` for Team) from a JS array — edit the array, not generated
  markup.

## Focus Areas publications list
- Each `.focus-card` has its own `<div class="focus-publications">`: a
  `<button class="focus-pub-toggle" onclick="toggleFocusPubs(this)">` plus
  `.focus-pub-body > .focus-pub-inner > ul.focus-pub-list` for just that
  tile's publications (no shared/combined list below the grid — tried and
  replaced). Uses the Participate (`.way-body`) JS-toggle mechanism, not
  `<details>` (animating `<details>` via `::details-content` was jerky in
  Firefox). Button label is one word; the "+"/"×" is CSS (`::after`), not text.
- Every `.focus-card` needs exactly 4 children (num, h3, p,
  `.focus-publications`) — it's a `subgrid` spanning 4 rows so toggles align.
- `.focus-pub-list` items: title wrapped in `<a>` to the DOI/landing page
  (`target="_blank" rel="noopener"`), then `<span class="focus-pub-meta">Venue
  · Year</span>` (short venue, e.g. "ACM FAccT · 2026"; arXiv → "Pre-print ·
  Year"). Authors deliberately omitted. Find the real DOI/URL by searching
  title+authors; if none exists (unpublished working paper), leave plain text,
  no fabricated URL. Titles not translated. No `white-space: nowrap` on the
  `<a>` — long titles must wrap or they overflow on mobile.

## Team section
- Former Members list (`formerMembers` in `assets/team.js`) is one line per
  person, no bio; optional `photo` field renders a round `.former-avatar`.

## Collapsible content
- Default pattern: plain `<details><summary>...</summary>...</details>`, no
  JS, `+`/`–` marker via `summary` CSS (see `.event-archive`, `.team-former`).
  Exception: Focus Areas publications (see above, JS-toggle for a reason).
  Summary label text is translated per language file.

## Non-website / email-task requests
- Not every email instruction maps to a site edit — some (LinkedIn drafts,
  research asks) are pure drafting tasks with no file to change other than
  the deliverable itself.
- No outbound email-sending tool exists; Gmail MCP needs OAuth the user must
  grant interactively, which a non-interactive run can't do. Never claim an
  email was sent — write the deliverable to a file so it becomes the
  OUTPUT_FILE attached to the reply.
- FuSo's LinkedIn company page (linkedin.com/company/future-society-hub/) is
  login-walled, not fetchable — ground drafts in futuresociety.ch/llms.txt
  instead and say so explicitly in the draft.

## Social icons
- Two places use inline-SVG social icons, not `<img>`/icon fonts: nav bar
  (`.nav-social`, LinkedIn only, in every `<nav>`) and Contact section
  (`.contact-social`, a flex row of icon links below the `fuso@unisg.ch`
  mailto, added below the postal address paragraph — LinkedIn + BlueSky so
  far). Both just set `color`/`hover:color:var(--accent)` on the `<a>` and
  rely on `fill="currentColor"` in the `<svg>` — reuse the exact `<path>`
  markup (Simple Icons-style paths) rather than re-fetching/re-drawing when
  adding another platform, and add new platforms to both places if the ask
  is "site-wide", not just one.

## CSS grid
- Sections use a shared `.grid` (grid-column per element), not flex/block.
  New full-width blocks after a `-grid` element typically use
  `grid-column: 3 / -1`, must be added to the tablet-breakpoint reset list
  (`grid-column: 1 / -1` around `.focus-intro, .focus-grid, ...`), plus a
  mobile-stacking rule if it's itself a multi-column grid.

## Nav submenu / audience deep links
- Participate's `<ul class="nav-sub">` links to
  `#participate-students|-researchers|-policy|-industry|-all`; a router in
  each file's inline script watches `hashchange`, calls `filterWays(key)` and
  scrolls to `#participate`. Unknown key → ignored, page behaves normally.
- Submenu rules are scoped to `#navMenu`/`#navMenu > li`, not `nav ul` —
  reverting to `nav ul` makes it inherit `position: absolute; top: 56px` and
  cover the page. Above 1100px items stretch to bar height for hover;
  below 1100px shortcuts render inline, always-visible.

## Project subsites (`2028gid/`)
- Standalone one-page essay, own `index.html` + inline `<style>`,
  English-only, no build step, borrows nothing from root `assets/` except
  `../assets/analytics.js`. Deliberately unlisted (no site link, not in
  `sitemap.xml`) — leave it that way unless asked.

## Hero pipeline line (`.hero-chain`)
- `.hero-sub.hero-chain` reads `Full Stack: Analyze › Build › Deploy ›
  Evaluate` (steps translated DE/FR, "Full Stack" label stays English).
  Deliberately plain text in `.hero-sub` styling, not the green `.block-item`
  chips from About's `.toolbox .process-flow` (boxes in hero were tried and
  rejected). Each `›` is bundled with the following step in a
  `<span class="chain-step">` (`white-space: nowrap`) so a line wrap can't
  strand an arrow — keep this pairing when reordering steps.
- Spelling is **"Full Stack"**, two words, no hyphen, everywhere (hero line +
  About `h3`), all three languages — keep in sync if wording changes.

## Asset hygiene
- Unreferenced images/banners/orphan logos were pruned Sept 2026; recoverable
  from git history if a use turns up.
- Songs live in `assets/audio/` (~22 MB, bulk of the repo), all `preload=
  "none"` — keep that on new tracks. `*:Zone.Identifier` files are
  `.gitignore`d, don't re-commit them.
- Below-the-fold images (team bricks, former-member avatars, funder/footer
  logos) carry `loading="lazy"`; nav/hero logos (above the fold) don't —
  match this when adding an image.

## Hero song easter egg (`.song-egg`)
- Music-note button in the hero's bottom-right opens an `EN/DE/FR/IT` pill;
  picking one plays that song via a single shared `<audio id="fuseSong">`
  (src swapped per pick, keeps `preload="none"` and the analytics.js src-based
  event naming meaningful). Note = stop button while playing, menu toggle
  otherwise. Escape/outside-click close the picker but don't stop playback.
  Picker codes are the SONG's language, not the page's — not translated.
  `I-faccio-FuSo.mp3` (Italian) is reachable only here (no `index.it.html`).
- Positioning is load-bearing: the note hangs off `.hero-logo` (wrapper
  around the logo img), tangent to the logo's inscribed circle at 4:30 via
  `calc(50% + 0.7071 * (50% + 25px))` — keep the formula, it holds at any
  logo size. The picker anchors to `.hero-logo` too (not the note), dropping
  into the clear band below — a pill this wide crosses circuit lines if
  opened from the note itself. Never move the note to the hero's top-right
  (collides with the nav EN/DE/FR switch). Colour is the logo's own accent
  green; hover/playing FILLS the circle rather than recolouring it.

## LinkedIn post draft requests
- Recurring email task: find a world-news story ≤2 days old that matches a
  FuSo focus area, draft a LinkedIn post tagging relevant entities, and tie it
  to a specific FuSo publication (Focus Areas `.focus-pub-list`s + `llms.txt`
  Publications/Key People). Must not repeat a **news story** already covered;
  reusing a **publication** is fine if the news hook/argument differs.
  New drafts go in `/linkedin-suggestions/` (older root-level
  `linkedin-post-draft*.md` files predate that convention, left in place).
  No email-sending tool exists — the draft file is the OUTPUT_FILE.
- Before picking a publication, `grep -l "doi.org\|arxiv\|openreview"
  linkedin-suggestions/*.md linkedin-post-draft*.md` and check each match's
  DOI against the site's focus-pub-lists — this is authoritative; a
  hardcoded list of "publications used so far" in these notes will drift and
  has been removed for that reason. As of Sept 2026, PermitBot (ICAIL 2026,
  no findable URL) and ShoppingCoach (Inclusive & Healthy Society tile) were
  still unused — repeated targeted searches for matching ≤2-day news have
  come up empty multiple times, surfacing only weeks-to-months-old stories;
  try a specific angle (named court case, product recall, passport mandate)
  before giving up on them. The Article 40(12) research-API audit paper
  (Bekavac & Mayer) has now been reused four times on four distinct stories
  (kill switch order, Meta CSAM-ad failure, PACE the Frontier, and the US
  DOJ's Sept 2026 court intervention backing Musk/X against the EU's €120m
  DSA fine) — it keeps resurfacing because Article 40(12) researcher-data-
  access is a recurring flashpoint in DSA enforcement news; treat it as a
  reliable fallback angle, not a sign to avoid the paper. FoodCoach was similarly stuck until a mainstream
  "AI recipes are untrustworthy" consumer-survey story (Inspired Taste, Sept
  2026) matched it not on nutrition content but on the trust/validation angle
  — FoodCoach's RCT-evaluated, purchase-data-grounded design vs. untested
  generative recipe text; worth remembering that a stuck publication's match
  may come from its *methodology* (rigorous evaluation, real behavioral data)
  rather than its subject-matter (food) when direct-topic searches keep
  missing. The Solid/MPC circular-economy paper was
  long stuck the same way on its decentralized-identity/supply-chain angle,
  until a UN panel brief on runaway multi-agent systems matched it from the
  *multi-agent-systems* side instead (the paper's other stated application,
  per Focus Areas "how" text and Jan Grau's team bio) — if a publication's
  news angle keeps drawing blanks, check whether it has a second stated
  application worth searching on before concluding it's unmatchable. FuSo's
  two books (*AI and Law*, Routledge/CRC 2024 — Tamò-Larrieux, Guitton &
  Mayer; *Designing for Privacy and its Legal Framework*, Springer 2018 —
  Tamò-Larrieux) are real publications but sit only in `llms.txt`/the site's
  JSON-LD `workExample` block, not in any Focus Areas `.focus-pub-list` —
  worth checking as an anchor when a fresh angle doesn't map cleanly to a
  listed paper; find the publisher landing page via WebSearch (no DOI
  exists) rather than fabricating one. A genuinely fresh, well-sourced story
  (e.g. a platform's own product announcement plus independent analyst
  commentary, not just wire-service recap) is fair game even without a
  regulatory/legal peg, as long as the FuSo focus-area/publication tie-in is
  substantive rather than cosmetic — see the Sept 2026 Amazon Seller Central
  agent-API draft, matched to *AI and Law* via the "who controls agent
  infrastructure" angle, not a compliance angle.
- WebSearch is unreliable for date-sensitive claims — verify the actual news
  hook against a primary source (WebFetch the regulator's own page, a wire
  service, or the original outlet) before treating it as fresh, watching for:
  (a) SEO/aggregator blogspam inventing specific agency names/dates (e.g. a
  fabricated "EU AI Act first-wave-of-inspections" story with named
  regulators that appears verbatim across multiple aggregator domains but
  isn't on the European Commission's own enforcement page); (b) old stories
  resurfacing as a late recap dated inside the window (a JUSTICE-charity
  legal-chatbot survey, a Connecticut court ruling — both were weeks old at
  the true first-press date); (c) flatly invented events (a nonexistent
  "Brazil Senate vote" WebSearch synthesized from nothing). When citing a
  specific bill number or figure from one outlet's summary, cross-check it
  against an independent tracker/source before using it as the anchor fact.
  Also watch for the same underlying incident resurfacing under a new
  headline days later (e.g. a wire piece on "legal accountability for
  autonomous AI hacks" republished the OpenAI–Hugging Face agent breach
  already used as the UN-panel draft's news hook three days earlier) — that
  counts as the same **news story** even with new framing/quotes, not a
  fresh one.

## FuSo Talks event list (`.event-box` "FuSo Talks")
- Each `.event-item`: `.event-name` (`.talk-title` + optional `.event-tag`
  parenthetical or `.bbl-tag` pill), `.event-speaker` ("Speaker:"/translated
  prefix + `.event-link`), optional `.event-coop`, then `.event-meta-row`
  (clock/lunch/pin `.event-icon` spans). `.bbl-tag` is a plain-text pill (CSS
  pill styling only, no actual icon glyph) normally reading "Brown Bag Talk";
  a talk singled out as tied to a specific project (e.g. CoCoDa) instead gets
  `.bbl-tag` text "Featured <a class="event-link" ...>CoCoDa</a> Talk" — the
  project name itself links out, same `.event-link` underline style used
  elsewhere. `.bbl-tag` text is left in English across DE/FR files (like
  "Full Stack"), only the `.event-speaker` prefix and any prose (e.g. "founder
  of X and Y" after a speaker name) get translated.

## Vanity redirect paths (`cocoda/`, `decode/`)
- Short URLs like `futuresociety.ch/cocoda` are a folder with one `index.html`
  that bounces via `<meta http-equiv="refresh">` + `location.replace(...)` +
  a visible fallback link + `<link rel="canonical">` + `noindex` — GitHub
  Pages has no server-side redirects. `cocoda/` → snsf-cocoda.github.io;
  `decode/` → futuresociety.ch/decode.github.io. To add another, copy an
  existing folder and swap the URL/title in all four places; keep out of
  `sitemap.xml`.
