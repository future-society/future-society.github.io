# Agent notes for future-society.github.io

## Site structure
- Single-page site, duplicated per language: `index.html` (EN), `index.de.html`,
  `index.fr.html`. No templating/build step — each is a full standalone copy.
  Any content change requested for "the website" generally needs to be applied
  to all three, with UI chrome (labels, buttons) translated but people's names,
  paper titles, and citations left as-is.
- Section markers use HTML comments (`<!-- FOCUS AREAS -->` etc.) matching the
  `<section id="...">` right below them — grep for the comment to jump to a
  section fast.
- Data-driven sections (Team, Projects/"Get concrete", Ways to participate) are
  rendered by inline `<script>` at the bottom of each HTML file (or
  `assets/team.js` for Team) from a JS array — edit the array, not generated
  markup.

## Focus Areas publications list
- Each `.focus-card` tile (Focus Areas section) has its own
  `<details class="focus-publications"><summary>More/Mehr/Plus</summary>
  <ul class="focus-pub-list">...` block listing only that tile's
  publications — there is no shared/combined list below the grid (that was
  tried and replaced). Add a new citation to the one tile it belongs to.
  The summary label is a single word only ("More"/"Mehr"/"Plus"); the
  leading "+" (and "–" when open) is drawn by the `.focus-publications >
  summary::before` CSS rule, not part of the text.
- `.focus-pub-list` items are just the paper title, wrapped in `<a>` linking
  to that paper's DOI/landing page (`target="_blank" rel="noopener"`) —
  authors/year/journal are deliberately omitted (full citations were tried
  and replaced by request). When adding a new citation, find its real
  DOI/URL (search by title+authors) rather than guessing one; if none is
  findable (e.g. unpublished working paper), leave the title as plain text
  with no link rather than fabricate a URL. Titles are not translated.
- `.focus-pub-list li a` must not have `white-space: nowrap` — long titles
  need to wrap, otherwise they overflow the tile width on narrow/mobile
  screens instead of the box staying fixed-width.

## Team section
- Former Members list (`formerMembers` in `assets/team.js`) is deliberately
  one line per person, no bio — but a `photo` field is supported and renders
  as a small round thumbnail (`.former-avatar`) before the name if given.

## Collapsible content
- Recurring pattern for "expand to see more" content: a plain
  `<details><summary>...</summary>...</details>`, no JS. Styled via a
  `summary` with `+`/`–` marker swap (see `.event-archive`, `.team-former`,
  `.focus-publications` in `assets/style.css`). Reuse this pattern rather than
  inventing a JS-toggled accordion for simple show/hide needs.
- Summary label text is translated per language file (e.g. "Past Events" /
  "Vergangene Veranstaltungen" / "Événements passés").

## Non-website requests (research/drafting/"send an email" tasks)
- Not every email instruction maps to a site edit — some (e.g. "check FuSo's
  LinkedIn, find world news, draft a LinkedIn post, email it to X") are pure
  research/drafting tasks with no natural file to change.
- No outbound email-sending tool exists in this environment; the Gmail MCP
  connector requires OAuth the user must grant themselves (claude.ai
  connector settings / `claude mcp` / `/mcp`), which a non-interactive run
  cannot do. Don't claim an email was sent — write the deliverable text to a
  new file in the repo root (e.g. `linkedin-post-draft.md`) instead, so it
  becomes the OUTPUT_FILE attached to the reply.
- FuSo's LinkedIn company page (linkedin.com/company/128604204) is
  login-walled and not fetchable by WebFetch — base drafts on the public
  website content (futuresociety.ch / llms.txt) instead and say so.

## CSS grid
- Sections use a shared `.grid` (CSS grid, `grid-column` per element) rather
  than flex/block layout. New full-width blocks placed after a `-grid` element
  typically reuse `grid-column: 3 / -1` (aligning with the content column, not
  the label column), and must be added to the tablet-breakpoint reset list
  (`grid-column: 1 / -1` around `.focus-intro, .focus-grid, ...`) in the
  `@media` block, plus a mobile-stacking rule if it's itself a multi-column
  grid.

## Nav submenu / audience deep links
- The nav's Participate entry carries a `<ul class="nav-sub">` of audience
  shortcuts linking to `#participate-students|-researchers|-policy|-industry`
  (`-all` is also accepted). Nothing on the page has those ids — a small
  router in each file's inline script watches `hashchange`, calls
  `filterWays(key)` and scrolls to `#participate` itself. Keys must match
  `WAY_AUDIENCES`; an unknown key is ignored and the page behaves normally.
- Because the submenu is also a `nav ul`, the horizontal-bar and collapsed-
  panel rules are scoped to `#navMenu` (and `#navMenu > li`), not `nav ul`.
  Keep it that way — reverting to `nav ul` makes the submenu inherit
  `position: absolute; top: 56px; left/right: 0` and it covers the page.
- Above 1100px `#navMenu` items are stretched to the full 56px bar height so
  the panel's `top: 100%` lands on the bar's bottom edge with no hover dead
  zone. Below 1100px there is no hover, so the shortcuts render inline and
  always-visible under Participate, centred like the rest of that menu.
- Labels are translated per file; the audience keys in the hrefs are not.

## Project subsites (`2028gid/`)

- `2028gid/` is a standalone one-page essay ("The 2028 Global Intelligence
  Dividend") in its own folder off the site root. It is a single
  self-contained `index.html` with its own inline `<style>`, English-only,
  no build step — it borrows nothing from the root `assets/` except
  `../assets/analytics.js`, so editing the FuSo stylesheet does not affect
  it and vice versa.
- It is deliberately unlisted: nothing on the main site links to it and it is
  not in `sitemap.xml`. Leave it that way unless asked.

## Hero pipeline line (`.hero-chain`)

- The hero's second sub-line used to read "Full Stack. From Insight to
  Impact." (untranslated in DE/FR). It is now the pipeline itself —
  `Full Stack: Analyze › Build › Deploy › Evaluate` — so the hero names what
  we do, not only what we are. The steps ARE translated (DE: Analysieren /
  Entwickeln / Einsetzen / Evaluieren; FR: Analyser / Développer / Déployer /
  Évaluer); the "Full Stack" label stays English, matching the About `h3`.
- It is deliberately PLAIN TEXT in the same type as the sentence above it:
  the `<p>` carries `class="hero-sub hero-chain"`, so the font comes from
  `.hero-sub` itself and cannot drift from it. Do not restyle it into the
  green `.block-item` chips of the About `.toolbox .process-flow` chain —
  boxes in the hero were tried and rejected.
- `.hero-chain` only adds `max-width: none` (the longer German verbs need
  the full column; `.hero-sub`'s 540px measure wraps them), the bottom
  margin, and the muted `.chain-arrow` separators. `.hero-sub` itself has
  `margin-bottom: 0` so the two `<p>`s read as consecutive lines of one
  block rather than as two paragraphs.
- Every `›` is wrapped with the step that follows it in a
  `<span class="chain-step">` (`white-space: nowrap`). Without that, a wrap
  on a narrow viewport strands an arrow at the end of the line above —
  German at 1100px and French on mobile both wrap here. Keep the pairing
  when adding or reordering steps.
- The full 8-block chain and the "Where other hubs stop at research…" blurb
  stay in About — the hero carries the short form only.
- Spelling is **"Full Stack"**, two words, no hyphen — in the hero line and in
  the About `h3` ("Full Stack: From Insight to Impact"), all three languages.
  The About heading used to read "Full-Stack"; it was unified in Sept 2026.
  Keep both in sync if the wording changes.

  an image.

## Vanity redirect paths (`cocoda/`, `decode/`)

- Short URLs like `futuresociety.ch/cocoda` are implemented as a folder with a
  single `index.html` whose only job is to bounce: `<meta http-equiv="refresh"
  content="0; url=...">` plus `location.replace(...)` plus a visible fallback
  link, with `<link rel="canonical">` to the target and `<meta name="robots"
  content="noindex">`. GitHub Pages serves no server-side redirects, so this
  client-side page is the mechanism — there is no `_redirects`/`.htaccess`.
- `cocoda/` → `https://snsf-cocoda.github.io/` (same URL the CoCoDa links in
  the three `index.*.html` files point at).
- `decode/` → `https://futuresociety.ch/decode.github.io/` (requested
  verbatim; that destination did not exist yet when the redirect was added).
- When adding another one, copy an existing folder and swap the URL/title in
  all four places (canonical, refresh, `location.replace`, fallback link).
  Keep them out of `sitemap.xml`.
