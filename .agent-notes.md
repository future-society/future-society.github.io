# Agent notes for future-society.github.io

## Site structure
- Single-page site, duplicated per language: `index.html` (EN), `index.de.html`,
  `index.fr.html`. No templating/build step — each is a full standalone copy.
  Any content change requested for "the website" generally needs to be applied
  to all three, with UI chrome (labels, buttons) translated but people's names,
  paper titles, and citations left as-is.
- Section markers use HTML comments (`<!-- FOCUS AREAS -->` etc.) matching the
  `<section id="...">` right below them — grep for the comment to jump to a
  section fast.
- Data-driven sections (Team, Projects/"Get concrete", Ways to participate) are
  rendered by inline `<script>` at the bottom of each HTML file (or
  `assets/team.js` for Team) from a JS array — edit the array, not generated
  markup.

## Focus Areas publications list
- Each `.focus-card` tile (Focus Areas section) has its own
  `<details class="focus-publications"><summary>More/Mehr/Plus</summary>
  <ul class="focus-pub-list">...` block listing only that tile's
  publications — there is no shared/combined list below the grid (that was
  tried and replaced). Add a new citation to the one tile it belongs to.
  The summary label is a single word only ("More"/"Mehr"/"Plus"); the
  leading "+" (and "–" when open) is drawn by the `.focus-publications >
  summary::before` CSS rule, not part of the text.
- `.focus-pub-list` items are just the paper title, wrapped in `<a>` linking
  to that paper's DOI/landing page (`target="_blank" rel="noopener"`) —
  authors/year/journal are deliberately omitted (full citations were tried
  and replaced by request). When adding a new citation, find its real
  DOI/URL (search by title+authors) rather than guessing one; if none is
  findable (e.g. unpublished working paper), leave the title as plain text
  with no link rather than fabricate a URL. Titles are not translated.
- `.focus-pub-list li a` must not have `white-space: nowrap` — long titles
  need to wrap, otherwise they overflow the tile width on narrow/mobile
  screens instead of the box staying fixed-width.

## Team section
- Former Members list (`formerMembers` in `assets/team.js`) is deliberately
  one line per person, no bio — but a `photo` field is supported and renders
  as a small round thumbnail (`.former-avatar`) before the name if given.

## Collapsible content
- Recurring pattern for "expand to see more" content: a plain
  `<details><summary>...</summary>...</details>`, no JS. Styled via a
  `summary` with `+`/`–` marker swap (see `.event-archive`, `.team-former`,
  `.focus-publications` in `assets/style.css`). Reuse this pattern rather than
  inventing a JS-toggled accordion for simple show/hide needs.
- Summary label text is translated per language file (e.g. "Past Events" /
  "Vergangene Veranstaltungen" / "Événements passés").

## CSS grid
- Sections use a shared `.grid` (CSS grid, `grid-column` per element) rather
  than flex/block layout. New full-width blocks placed after a `-grid` element
  typically reuse `grid-column: 3 / -1` (aligning with the content column, not
  the label column), and must be added to the tablet-breakpoint reset list
  (`grid-column: 1 / -1` around `.focus-intro, .focus-grid, ...`) in the
  `@media` block, plus a mobile-stacking rule if it's itself a multi-column
  grid.
